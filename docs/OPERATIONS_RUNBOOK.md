# Operations Runbook

## Normal startup: portable

```powershell
.\.venv\Scripts\Activate.ps1
python -m eci.cli health
python -m streamlit run app.py
```

## Normal startup: Docker profile

```powershell
docker compose up -d
python -m eci.cli health
python -m streamlit run app.py
```

## Normal ingestion

```powershell
python -m eci.cli ingest path\to\approved_file.csv
```

Review:

1. CLI summary
2. `ingestion_runs` record
3. Rejected CSV
4. `rejected_records` table
5. SQL row counts
6. Vector health count

A `PARTIAL` run is expected when one or more rows are quarantined while valid rows complete both destinations.

## Health checks

```powershell
python -m eci.cli health
```

Expected components:

- Database: connected
- Vector store: ready and document count available

## Rebuild portable state

```powershell
python scripts\bootstrap_demo.py --reset
```

This deletes the portable SQLite database and local vector index, regenerates synthetic input, reingests it, and recreates Power BI CSVs.

## Rebuild Docker development state

Destructive command:

```powershell
docker compose down -v
.\scripts\start_enterprise_stack.ps1
```

The `-v` option deletes MySQL and Weaviate volumes. Use only for disposable local data.

## SQL succeeds but vector indexing fails

Symptoms:

- Ingestion run is `FAILED`.
- SQL records may exist.
- Vector count may be incomplete.

Recovery:

1. Correct the vector service or credential issue.
2. Run health checks.
3. Rerun the exact same source file.

Unchanged SQL records are skipped. Vector records are upserted by deterministic ID. The new run can complete without duplicating business records.

## OpenAI request fails

Check:

- `OPENAI_API_KEY` exists only in `.env`.
- API access and billing are active.
- Model IDs are valid for the account.
- The computer can make outbound HTTPS connections.
- Timeout and retry settings are reasonable.
- No key appears in logs.

The application converts provider exceptions into a safe service error and preserves the underlying stack trace only in local structured logs.

## MySQL authentication fails

Check:

- Docker Desktop is running.
- `docker compose ps` shows MySQL healthy.
- `.env` has the Docker profile.
- `DATABASE_URL` password is URL-encoded.
- Port 3306 is not occupied by another local MySQL service.

The generated environment script URL-encodes the application password automatically.

## Weaviate authentication fails

Check:

- REST 8080 and gRPC 50051 are both published.
- `WEAVIATE_API_KEY` matches the value used when the volume was first created.
- Anonymous access remains disabled.
- The Python client and database versions remain compatible.

If credentials changed after the volume was created, recreate the disposable development volume or manage users deliberately.

## Embedding dimension mismatch

This means document vectors already in the index were generated by a different model or local dimension.

Recovery:

1. Confirm the intended embedding model.
2. Rebuild the vector collection or local index.
3. Reingest from the SQL system of record or validated processed file.

Never append one model's vectors to an index built with another model.

## Backup targets

Portable:

- `data/eci_demo.db`
- `data/vector/local_index.json`
- Valid processed CSVs
- Rejected CSVs

Docker development:

- MySQL volume or logical dump
- Weaviate volume or backup
- `.env` stored securely and separately
- Source and processed files

A production plan must include automated backups and regular restore tests.
